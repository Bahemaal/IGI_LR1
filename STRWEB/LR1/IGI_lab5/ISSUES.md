# Реестр дефектов (ISSUES)

Дефекты найдены при сверке требований ([`docs/requirements.md`](docs/requirements.md)) с работающим приложением
(см. [`docs/verification.md`](docs/verification.md)). Все дефекты имеют статус **Открыт**.

Серьёзность: **Блокирующая** — приложение нельзя установить или запустить; **Критичная** — сбой основного сценария
или обход защиты; **Высокая** — искажение данных или денег, утечка данных; **Средняя** — нарушение правил предметной
области или обходной путь есть; **Низкая** — мелкое неудобство или риск.

Автоматическое подтверждение: тест с таким именем находится в `apps/core/tests_requirements.py` и помечен
`@known_defect`. Чтобы увидеть реальную ошибку, временно уберите декоратор.

## Описание

### ISS-001. В `requirements.txt` нет `requests` — Блокирующая
- **Где:** `requirements.txt`; пакет `requests` импортируют `apps/core/currency.py` и `ip_logger.py`.
- **Шаги:** создать чистое окружение, `pip install -r requirements.txt`, `python manage.py check`.
- **Ожидается:** проверка проходит, сайт запускается.
- **Фактически:** `InvalidTemplateLibrary … ImportError raised when trying to load 'apps.core.templatetags.custom_tags': No module named 'requests'`; не работает ни одна страница.
- **Проверка:** `NonFunctionalRequirements.test_NFR05_declared_dependencies_match_imports`.
- **Рекомендация:** добавить `requests` в `requirements.txt`.

### ISS-002. Compose поднимает PostgreSQL, приложение использует SQLite — Средняя
- **Где:** `docker-compose.yml` (сервис `db`), `cosmet_center/settings.py` (`ENGINE = sqlite3`).
- **Ожидается:** база из compose используется приложением.
- **Фактически:** контейнер PostgreSQL запускается впустую, `psycopg2-binary` не используется, данные лежат в SQLite внутри смонтированной папки проекта.
- **Проверка:** `test_NFR05_compose_database_matches_settings`.
- **Рекомендация:** читать параметры БД из переменных окружения (`POSTGRES_*`) либо убрать сервис `db`.

### ISS-003. Заказ с действующим промокодом падает с ошибкой 500 — Критичная
- **Где:** `views.checkout_view`: `total = subtotal * (1 - promo.discount_percent / 100)`.
- **Шаги:** добавить услугу в корзину, оформить заказ с кодом действующего промокода.
- **Ожидается:** заказ создан, итог 180.00 для 2×100.00 и скидки 10%.
- **Фактически:** `TypeError: unsupported operand type(s) for *: 'decimal.Decimal' and 'float'`, ответ 500, заказ не создан.
- **Проверка:** `CartOrderRequirements.test_FR07_valid_promo_applies_discount`.
- **Рекомендация:** считать через `Decimal` и округлять до копеек: `(subtotal * (100 - p) / 100).quantize(Decimal("0.01"))`.

### ISS-004. Все заказы получают статус «Оплачен» — Высокая
- **Где:** `views.checkout_view`, `Order.objects.create(..., status="paid")`.
- **Ожидается:** при оплате «Наличные при визите» статус «Новый»; «Оплачен» только после оплаты.
- **Фактически:** статус всегда «Оплачен», значение `new` не используется; платёжного шлюза нет, поэтому и карточный заказ «оплачен» без оплаты.
- **Проверка:** `test_FR08_cash_order_is_new_until_paid`.
- **Рекомендация:** создавать заказ в статусе `new`, менять его на `paid` при подтверждении оплаты.

### ISS-005. Клиент сам ставит любой статус записи — Высокая
- **Где:** `forms.AppointmentUpdateForm` (поля `status`, `notes`), `views.update_appointment`.
- **Шаги:** клиент открывает «Изменить» у своей записи, выбирает «Завершено», сохраняет.
- **Ожидается:** клиент меняет только примечание; подтверждает и завершает врач или администратор.
- **Фактически:** статус меняется; допустим любой переход, в том числе из «Завершено» и «Отменено».
- **Проверка:** `AppointmentRequirements.test_FR13_client_cannot_self_confirm_or_complete`.
- **Рекомендация:** ограничить поля формы по роли и проверять допустимые переходы (см. `docs/appointment-lifecycle.md`).

### ISS-006. Обход прав доступа к записям — Критичная
- **Где:** `views.update_appointment`, `views.delete_appointment`.
- **Шаги:** войти пользователем без профиля клиента и врача (например, созданным в админке) и отправить POST на `/appointment/<id>/edit/` или `/delete/`; либо войти врачом и удалить запись к другому врачу.
- **Ожидается:** отказ.
- **Фактически:** проверки выполняются только при наличии `client_profile` (и `doctor_profile` при изменении), поэтому остальные проходят; при удалении проверки врача нет вообще. Запись изменена или удалена.
- **Проверка:** `test_FR15_user_without_role_cannot_edit_appointment`, `…_cannot_delete_appointment`, `test_FR15_doctor_cannot_delete_foreign_appointment`.
- **Рекомендация:** единая функция прав: владелец-клиент, врач своей записи, `is_staff`; всем остальным отказ.

### ISS-007. «Отмена» удаляет запись и оплату — Высокая
- **Где:** `views.delete_appointment` (`appt.delete()`), `Sale.appointment` с `on_delete=CASCADE`.
- **Ожидается:** запись получает статус «Отменено» и остаётся; завершённую запись с оплатой отменить нельзя.
- **Фактически:** запись удаляется физически, статус `cancelled` недостижим из интерфейса; удаление завершённой записи каскадом удаляет `Sale` и искажает выручку.
- **Проверка:** `test_FR14_cancel_keeps_record_with_cancelled_status`, `test_FR14_completed_appointment_with_payment_cannot_be_cancelled`.
- **Рекомендация:** мягкая отмена статусом, запрет отмены завершённых, `on_delete=PROTECT` для `Sale`.

### ISS-008. Двойное бронирование врача — Высокая
- **Где:** `forms.AppointmentForm`.
- **Шаги:** два клиента записываются к одному врачу на одно и то же время.
- **Ожидается:** вторая запись отклонена.
- **Фактически:** созданы обе записи.
- **Проверка:** `test_FR12_double_booking_rejected`.
- **Рекомендация:** проверять пересечение интервалов с учётом `Service.duration` в `clean()` внутри транзакции.

### ISS-009. Запись к неактивному врачу и на чужую услугу — Средняя
- **Где:** `forms.AppointmentForm` (поля `doctor`, `service` берут все объекты).
- **Ожидается:** выбор ограничен активными врачами и услугами, которые врач оказывает.
- **Фактически:** запись создаётся и к неактивному врачу, и на услугу, которой нет в списке услуг врача.
- **Проверка:** `test_FR12_doctor_must_provide_service`, `test_FR12_inactive_doctor_not_bookable`.
- **Рекомендация:** ограничить queryset и проверять связь врач-услуга в `clean()`.

### ISS-010. Запись вне расписания врача — Средняя
- **Где:** `forms.AppointmentForm`; модель `Schedule` не участвует в проверке.
- **Фактически:** при графике 08:00–20:00 запись на 23:00 принимается.
- **Проверка:** `test_FR12_booking_only_within_doctor_schedule`.
- **Рекомендация:** сверять день недели и время с `Schedule` врача.

### ISS-011. Врач не может подтвердить приём из кабинета — Средняя
- **Где:** `templates/doctor_profile.html` (нет ссылок «Изменить»), `views.update_appointment` (`redirect("profile")`).
- **Шаги:** врач открывает `/appointment/<id>/edit/` по прямому адресу и сохраняет.
- **Ожидается:** возврат в «Кабинет врача».
- **Фактически:** перенаправление на `/profile/`, затем на главную с сообщением «Ваш профиль не найден».
- **Проверка:** `test_FR16_doctor_returns_to_cabinet_after_status_change`.
- **Рекомендация:** добавить в кабинет врача действия «Подтвердить» и «Завершить», перенаправлять по роли.

### ISS-012. После входа теряется `?next=` — Низкая
- **Где:** `views.user_login` всегда делает `redirect("home")`.
- **Фактически:** `/profile/` → `/login/?next=/profile/` → после входа главная страница.
- **Проверка:** `AccountRequirements.test_FR10_login_returns_to_requested_page`.
- **Рекомендация:** учитывать `next` с проверкой `url_has_allowed_host_and_scheme`.

### ISS-013. Открытое перенаправление в `cart_add` — Средняя
- **Где:** `views.cart_add`: `redirect(request.POST.get("next") or "cart")`.
- **Шаги:** POST на `/cart/add/<id>/` с `next=https://evil.example/phish`.
- **Фактически:** ответ перенаправляет на внешний сайт.
- **Проверка:** `NonFunctionalRequirements.test_NFR02_no_open_redirect_in_cart_add`.
- **Рекомендация:** проверять адрес через `url_has_allowed_host_and_scheme`.

### ISS-014. Добавление в корзину по GET — Низкая
- **Где:** `views.cart_add` не ограничивает метод; `cart_remove` тоже меняет состояние по GET.
- **Фактически:** переход по ссылке `/cart/add/<id>/` меняет корзину (предзагрузка браузера, чужая ссылка).
- **Проверка:** `test_NFR02_cart_add_does_not_change_state_on_get`.
- **Рекомендация:** `@require_POST` для изменяющих действий.

### ISS-015. `/set-currency/` без CSRF-защиты — Низкая
- **Где:** `views.set_currency` (`@csrf_exempt`, `except:` без типа исключения).
- **Фактически:** запрос без токена принимается.
- **Проверка:** `test_NFR02_csrf_enforced_on_set_currency`.
- **Рекомендация:** убрать `csrf_exempt`, передавать токен в `fetch` (заголовок `X-CSRFToken`), ловить конкретные исключения.

### ISS-016. Страница заказа открыта посторонним — Высокая
- **Где:** `views.order_success` (`get_object_or_404(Order, pk=pk)` без проверки владельца).
- **Шаги:** без входа открыть `/order/<номер>/success/`, перебирая номера (1, 2, 3…).
- **Ожидается:** отказ посторонним.
- **Фактически:** страница показывает любому ФИО заказчика, состав заказа, сумму и способ оплаты.
- **Проверка:** `test_FR06_order_success_not_visible_to_strangers`.
- **Рекомендация:** хранить номер заказа в сессии оформившего или использовать неугадываемый токен.

### ISS-017. Выручка не учитывает заказы — Средняя
- **Где:** `views.admin_statistics`: `Sale.objects.aggregate(Sum("amount"))`.
- **Фактически:** оплаченные онлайн-заказы в выручку не входят.
- **Проверка:** `MiscRequirements.test_FR20_revenue_includes_paid_online_orders`.
- **Рекомендация:** добавить `Order(status="paid")` (после исправления ISS-004).

### ISS-018. Отзывы публикуются без модерации — Низкая
- **Где:** `Review.is_approved` по умолчанию `True`.
- **Фактически:** отзыв виден сразу, хотя в админке поле «Одобрен» редактируется как флаг модерации.
- **Проверка:** `ReviewRequirements.test_FR17_new_review_awaits_moderation`.
- **Рекомендация:** значение по умолчанию `False`.

### ISS-019. Небезопасная конфигурация — Высокая
- **Где:** `cosmet_center/settings.py`: `DEBUG = True`, `SECRET_KEY = 'django-insecure-…'` в репозитории, `ALLOWED_HOSTS = ['*']`.
- **Фактически:** при развёртывании раскрываются внутренности приложения, подписи сессий можно подделать.
- **Проверка:** `test_NFR03_production_ready_settings`.
- **Рекомендация:** брать значения из переменных окружения, сменить скомпрометированный ключ.

### ISS-020. Ошибка ipapi.co не кэшируется — Средняя
- **Где:** `ip_logger.get_ip_info`: кэшируется только успешный ответ; запрос синхронный, таймаут 6 с.
- **Фактически:** при недоступности сервиса каждая загрузка `/profile/` ждёт до 6 с. IP клиента передаётся стороннему сервису, а политика конфиденциальности упоминает только сбор IP для аналитики и безопасности.
- **Проверка:** `ExternalServiceFailureRequirements.test_NFR06_ip_lookup_failure_is_cached`.
- **Рекомендация:** кэшировать ошибки на несколько минут, вынести вызов из запроса, описать передачу IP в политике.

### ISS-021. `/multitasking/` доступна анониму и ресурсоёмка — Низкая
- **Где:** `multitasking.multitasking_view`: на каждый GET создаётся пул из 4 процессов.
- **Фактически:** запрос выполняется около 2.75 с; частые обращения загружают сервер.
- **Проверка:** `test_NFR02_heavy_demo_page_not_public`.
- **Рекомендация:** ограничить доступ (`staff`) или отключить вне учебного режима.

### ISS-022. Существующие тесты проекта падают — Низкая
- **Где:** `apps/core/tests.py`.
- **Фактически:** из 57 тестов: ошибка в `test_adult_exactly_18` (`ModuleNotFoundError: dateutil`, импорт стоит вне `try`, пакета нет в зависимостях) и два падения в `ServiceFilterTest` (`assertNotContains`, но название услуги всегда присутствует в списке подсказок `datalist`).
- **Проверка:** `test_NFR05_test_dependencies_declared`; прогон `python manage.py test apps.core`.
- **Рекомендация:** убрать зависимость от `dateutil` или добавить пакет; проверять `response.context["services"]`.

### ISS-023. У переключателя валюты нет подписи — Низкая
- **Где:** `templates/services.html`, `<select onchange="setCurrency(this.value)">`.
- **Проверка:** `test_NFR04_every_form_control_has_label`.
- **Рекомендация:** добавить `<label>` или `aria-label`.

### ISS-024. В репозитории лежат служебные и пользовательские файлы — Низкая
- **Где:** `.gitignore` проекта не исключает `db.sqlite3`, `.idea/`, `media/`.
- **Фактически:** в Git попали база с учётной записью суперпользователя (хэш пароля), настройки IDE и загруженные изображения.
- **Рекомендация:** добавить в `.gitignore`, удалить из индекса (`git rm --cached`); хранить демо-данные в фикстуре.

### ISS-025. Расписание врача не проверяется — Низкая
- **Где:** модель `Schedule`.
- **Фактически:** допускается `time_end` раньше `time_start`; пересечения интервалов не проверяются.
- **Проверка:** `MiscRequirements.test_FR24_schedule_end_must_be_after_start`.
- **Рекомендация:** метод `clean()` и ограничение на уровне БД.

### ISS-026. Поиск не находит кириллицу другого регистра — Средняя
- **Где:** `views.services_list`, `views.doctors_list` (`icontains`) на SQLite: `LIKE` не приводит регистр кириллицы.
- **Шаги:** искать «пилинг» при названии «Пилинг» либо «иванова» при ФИО «Иванова Анна».
- **Ожидается:** запись найдена.
- **Фактически:** ничего не найдено; запрос того же регистра, что в данных, работает.
- **Проверка:** `test_FR02_services_search_case_insensitive_cyrillic`, `test_FR04_doctors_search_case_insensitive_cyrillic`.
- **Рекомендация:** перейти на PostgreSQL (связано с ISS-002) либо хранить нормализованное поле для поиска.

### ISS-027. Ошибка форматирования журнала при изменении и отмене записи — Низкая
- **Где:** `views.update_appointment`, `views.delete_appointment`: `logger.info("Appointment %d …", pk, …)`, а `pk` из `re_path` приходит строкой.
- **Фактически:** в консоли `--- Logging error --- TypeError: %d format: a real number is required, not str`; записи об этих действиях в журнал не попадают.
- **Проверка:** `NonFunctionalRequirements.test_NFR08_appointment_update_and_delete_log_records_are_valid`.
- **Рекомендация:** использовать `%s` либо конвертер `<int:pk>` в маршрутах.

### ISS-028. Chart.js загружается без версии и контрольной суммы — Низкая
- **Где:** `templates/admin_statistics.html`: `https://cdn.jsdelivr.net/npm/chart.js`.
- **Фактически:** страница статистики зависит от доступности CDN и подтягивает любую свежую версию.
- **Рекомендация:** зафиксировать версию, добавить `integrity`, либо хранить файл в `static/`.
